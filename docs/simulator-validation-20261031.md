## 设置持久化加固（2026-10-31）

### 调查结论

现象：更新后设备词书从 CET-6 回到 CET-4。用新增启动日志取证，两次连续启动都是：

```
restored: book=0 daily=10 level=2 streak=0
settings verified on boot
```

`level=2` 是更早会话写入、并跨越多次更新与重启仍然恢复成功的**非默认值**，证明 NVS 本身可持久化；`book` 的存储值确实为 0（最后一次写入就是 0，而非读取失败）。

真正的系统性缺陷不在 NVS，而在旧实现：六处各自调用 `nvs_open` 的写入**全部忽略返回值**（open/set/commit 任一失败都静默丢弃），且每次只写一个键，运行时状态与已落盘值可能长期不一致，一旦写入失败只能表现为“重启后莫名回退”。

### 修改

- 新增 `main/wq_settings.c/.h`：单一记录（book/music/daily/level/streak/lastday/days），
  `wq_settings_save()` 执行 **写入 → commit → 重新打开只读逐字段读回比对**，不一致返回失败并打印具体字段；
  单次失败自动重试一次（覆盖 flash 擦除/并发提交后的瞬时失败）。
- `wq_settings_load()` 对缺键填默认、越界值钳位（daily 非法回默认、book 超出词书数量回 0、level≥1）。
- 三种后端共用同一记录布局：设备用 NVS、模拟器用进程内 RAM、回归测试用 `-DWQ_KV_TEST` 注入故障。
- `wordquest_ui.c` 移除全部直接 `nvs_*` 调用与重复状态字段（`wordquest_ui_t` 只保留动画状态），
  所有持久化统一走 `save_cfg()`；启动时打印恢复值并执行一次**开机自检**（重写+校验完整记录），
  可把旧版本只写了部分键的记录升级为完整记录。
- `pc/platform_pc.c` 删除引用已移除字段的调试打印。

### 回归用例（`.agents/analysis/test_settings.c`，10 组）

默认值、词书跨重启保持、**写入被静默丢弃可检出**、**存储陈旧可检出**、commit 失败、存储不可用、
**瞬时失败自动重试后成功**、范围钳位、损坏值加载时被纠正、部分键缺失回落默认。

运行：`gcc -std=c11 -Wall -Wextra -Werror -O2 -DWQ_KV_TEST -I <app>/main .agents/analysis/test_settings.c <app>/main/wq_settings.c -o t && ./t`

### 真机证据

app `d7f84c64…`（ui_apps 不变），设备连续两次启动（第二次用 `--skip-build` 强制重启）均输出相同的
`restored:` 与 `settings verified on boot`，即“写入 → 重启 → 读回”完整往返成功。

## 分区余量结论（2026-11-01）

构建时 `check_sizes` 会对 `factory`（0x20000，1.75MB）报“分区过小”，因为应用二进制已增长到 1.84MB。**这不是运行路径问题**：固件启动时新增日志取证

```
running partition: ota_0 @0x210000 size 12736 KiB
```

应用只从 `ota_0`（12.4MB）启动；`factory` 是保留恢复前缀里未使用的遗留槽，`system-update` 也从不写入它（写入目标是 0x210000 的 `ota_0`）。
按仓库规范（不得为通过检查而改动保留分区布局），**不重构分区表**，改为把这条证据固化在启动日志里，任何一次启动都能核对实际运行槽位与容量。
`ui_apps` 1,507,664 / 1,572,864 仍余 65KB，属于后续注意项。

## 遗忘曲线复习调度（2026-11-01）

- 每词 2 bit **阶段**（0/1/2）+ 每阶段“下次到期日”，阶段间隔 **1 / 3 / 7 天**；整份记录随词书独立，走 `wq_settings` 校验型 blob（键 `srs<book>`，1032 字节）。
- 选词规则：到期的顽固词 → 到期的其他已学词 → 不足时再用原有蓄水池抽样补齐；时钟未知（`day=0`）时退化为原随机复习，保证模拟器与无网络设备不空转。
- 答题反馈：答对升一阶段（封顶 2），答错回到阶段 0 并同时记入顽固词；一轮复习开始后把已服务阶段的下次到期日推后，避免同一批词天天复现。
- 新学词当天进入阶段 0 但**次日才到期**，当天的记忆检测由同一轮内的即时测验证。

| 离线录音包（6084 词 × 8 kHz/8-bit ≈ 0.6 s） | ≈29 MB | 不可行：整片 flash 16 MB，`ui_apps` 仅余 ≈65 KB |
| 离线包 + 4-bit ADPCM | ≈14.6 MB | 仍不可行（无空闲分区，且会侵占保留前缀） |
| 运行时按需下载音源 | 需 Wi-Fi 配网入口 + 持久缓存分区 | 当前产品无配网 UI、无空闲分区，列为后续 |
| **设备端 IPA 音素合成** | ≈7 KB 代码/表，零资源 | **采用**：离线、即时、覆盖全部词条 |

### 实现

- `main/wq_speech.c`：把词库自带的 IPA 转成 8 kHz/16-bit PCM。元音用三共振峰合成（F1/F2/F3 见 `PHONES` 表），鼻音/边音加气流噪声，擦音用高通（s/ʃ）或低通（f/θ）噪声带，塞音用“闭音+爆破”，`h` 为气声；`ˈ` 重音加长，`ː` 长音延长前一元音。
- `wq_audio_speak()`：合成一次写入静态 38 KB 缓冲，作为独立“人声通道”与 BGM/SFX 混音，**朗读期间音乐压到 15%** 保证可懂度。
- 交互：单词区域覆盖**透明按钮**（`word_tap` / `learn_word_tap`）触发朗读；学习页标题提示“· 点词朗读”，答题页提示“点单词朗读 · 选择正确意思攻击 Boss”，点后反馈“再次点击单词可重听”。
- 覆盖：6084 条词条中 6024 条有 IPA 可发声；60 条为空 IPA，点击无声音（已知限制）。

### 验证

- 新增 `speech_test.c`：空/垃圾输入返回 0、微小缓冲拒绝、真实单词时长与振幅合理、**确定性**（同 IPA 同输出）、长音与重音确实更长、超长输入被截断、**全库扫描**（6024 条，0 条静音、无一处削波）。
- 声学自检（导出 WAV 分析）：abandon 0.48 s / absolute 0.57 s / international 0.77 s，能量呈音节起伏，过零率在 1.0–4.3 kHz 间切换（浊音↔擦音），峰值 20221 未削波。
- 六套回归全绿（发音 / 设置+blob / 顽固词+收藏 / SRS+报表 / 模型 / 文本）。
- 模拟器点验：点击单词触发朗读（答题页反馈随之变化），未误触其它控件。

真机：app `95a6bf52…`，ui_apps `5af84958…`，`running partition: ota_0` + `restored: book=1 daily=10 level=2 streak=0`，idle、crash 0、内部堆余 204 KB（人声缓冲 38 KB 为静态占用）。
**听感需人工确认**：本机无法录制设备扬声器，音色是否可接受需上手试听；若清晰度不足，可调 `PHONES` 共振峰表或提高采样率到 16 kHz。

### 这轮踩到的 GSP 规律（已固化到记忆）

1. **新建的 hidden 容器 + 子件整棵子树不渲染**（与既有 overlay 完全同构也不行），改为**根级控件逐个显隐**后正常。

4. **多行动态文本不可靠**（`overflow: clip` + 行距也不行）→ 每行一个按钮 + 一个标签最稳。
5. **全量 CJK 字库不能挂在新字号上**：给 15px 行标签挂 `charset_cjk.txt` 让 bundle 从 1.5MB 涨到 3.1MB（两套全量图集），统一到 16px 共享既有图集后回到 1.53MB。

- **图片 393,553 字节**：27 张里只有 19 张被场景引用，精灵已是 16–64 色；对抖动像素画自动选中的 JPEG 比 QOI 更小（主页图 108KB vs 142KB），换编码无收益。
- 结论：除「胜利页整图 110KB 换成纯色 + 徽章」这一档外，没有既保画质又明显省空间的做法；当前余量足够支撑小功能迭代。

### 二次调整：背景不再被遮住（v22）

用户反馈「背景图大多被遮挡掉了，有没有两全其美的方法」。原因不在地图本身，而在 4 行控件（状态／词书／主按钮／工具）本身就吃掉 480px 里的 230px，怎么排都会压住营地。做法是把画面重新分工：

| 区域 | 内容 |
| --- | --- |
| 0–264 | 营地舞台：`home_bg` 上移 110px（只露出源图 y=110–374 的这一段），角色、篝火、帐篷全部完整可见 |
| 0–190 | 顶部渐隐遮罩 `home_scrim`（480×190，alpha 240→0）：压住树冠，给标题和状态行一个可读底；标题/副标题/状态行各加 2px 黑色投字 |
| 98–124 | 一行状态：`已斩 9/2345 · Lv.2 · 打卡 0 天`（16px，米色）；原来的三格告示牌撤掉 |
| 264–480 | 控制区：半透明底板 `home_deck`（480×216；顶 16px 渐变、上部 RGBA 190、源图画完的地方转不透明）+ 词书 200×44 / 主按钮 416×52 / 工具 95×40，上下内边距各 16、行距 8 |

关键实测：**容器**的 `bg_color` 带 alpha 和 `bg_opacity` 在本平台不会与下层图混合（试过 190/200 都无效），要做半透明遮罩必须用**带 alpha 的图片** —— 改成 `img/home_deck_190.png`（RGBA 15,22,17,190）后才真正透出草地。`home_scrim`、`home_deck` 都是图片，同样要挂 `bind_target: visible` 并加进 `WQ_HOME_CHILDREN`，否则会吞掉答题页选项的点击。
